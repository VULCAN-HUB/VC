# 1. 엔진 상태 — **진짜 결함이었다. 그것도 큰 것**

네 갈라내기가 정확했다:

> API 조회 경로는 실제 성공. **GUI 엔진상태 조회 경로**의 실패 가능성이 있다.

원인은 한 줄이었다.

```
창이 서버에 걸 때 쓰는 것(ServerLink)의 설정 파일 자리가 **빈 글자**였다
  → 빈 자리를 읽다 조용히 실패 → 토큰이 빈 채로 남음
  → 토큰이 없으면 **아예 걸지도 않고** 곧바로 「못 물어봤다」를 돌려준다
```

**창은 서버에 전화를 건 적이 없다.** 서버가 멀쩡히 답하는데도 그랬다.
이제 아무도 자리를 안 알려 주면 **스스로 설정 파일을 찾는다.**

★ 이건 엔진 줄만의 일이 아니다. 같은 전화를 쓰는 **원격 승인 칸·모델 고르는 칸**도
같이 죽어 있었다. 그쪽도 이제 산다 — **재 줄 것에 넣었다.**

★ 네가 「전체 서버가 죽었다고 판단하지 않는다」로 멈춘 것이 이 결함을 찾게 했다.
API 는 되는데 창만 안 된다 → **창 쪽 경로**라는 갈라내기가 곧 원인 자리였다.

# 2. 장문 부분 읽기 — 네가 낸 값이 이 기능의 첫 실측이다

```
검색 목록      356자   (본문 없음 · chars 3069 · headings 5)
한 토막        849자   (본문 775자 = 원문의 25.3%)

```

★ **목록이 356자, 전체가 3226자.** 열 배다. 이게 이 판에 넣은 두 단 꺼내기의 값이다.
H1 까지 headings 에 들어온 것도 맞는 동작이다(문서 제목도 갈 수 있는 자리다).

# 3. 적합률 4/5 로 내려간 것 — **맞는 동작이다**

손으로 넣은 원본에는 앞머리가 없다. **VC 는 사람이 넣은 파일을 말없이 고치지 않는다.**
그래서 「옛 판 1장」으로 세는 것이 옳다. `--판올리기 --쓴다` 를 안 돌린 것도 옳다 —
그건 **파일을 고치는 일**이라 사람이 정할 자리다.

# 4. 맞짝 1 — 이것도 맞는 동작이다

벡터가 다 만들어진 뒤에야 이음선이 생긴다. 네가 「벡터 1/4 때의 0 과 직접 비교하지
않는다」고 적은 것이 정확하다. **잣대에 「벡터가 다 찼을 때」를 같이 적자.**

```
맞짝 수는 **벡터 N/N 이 된 뒤**에 잰다
```
