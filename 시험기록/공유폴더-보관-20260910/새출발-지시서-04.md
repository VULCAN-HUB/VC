# 1. ★ 씨앗이 첫 흡수를 막던 것 — **결함 맞다. 고쳤다**

네 진단이 정확하다. **창을 한 번 켠 것이 죄가 됐다.**

```
창이 처음 켜지며 만드는 씨앗 글 「VC」에 아무 표시가 없었다
  → 흡수의 「사람이 손댄 기록」 막이가 그걸 사람 글로 봤다
  → 새 창고의 첫 흡수가 통째로 막혔다
```

이제 씨앗에 **`지은이: "씨앗"`** 이 박힌다. 그리고 표시가 없던 옛 씨앗까지 덮으려고
**`kind: "agent"`** 도 같이 본다 — **네 창고를 다시 만들 필요 없다.**

★ 사람이 그 씨앗을 **실제로 고치면** `edited_by: "사람"` 이 붙고, 그때는 다시 지킨다.
검사에 둘 다 박았다(안 고친 씨앗은 안 세고, 고친 씨앗은 센다).

```
[잰 것] 씨앗 1장 있는 창고에 --흡수 --쓴다
        v0.1.82 : 「사람이 손댄 기록이 1개 있다. 다시 붓지 않는다」 · 종료값 1
        v0.1.83 : 막이를 안 만나고 문지기까지 그대로 간다 ✓
```

**`--그래도쓴다` 를 안 쓴 것이 옳다.** 그걸 썼으면 이 결함이 안 보였다.

# 2. 물음 — 「본 것」의 단위는 파일이 아니라 **조각**이다

맞다. 그리고 **내 지시서 01 이 틀리게 적었다.**

```
파일 10개  →  조각 14개  →  본 것 14 = 후보 3 + 겹침 0 + 너무 짧다 9 + 빈 파일 2
```

한 파일이 소제목마다 조각으로 갈라진다(사람이 글을 나눠 놓은 자리가 뜻이 갈리는
자리라서). 그래서 **「본 것」은 조각 수**다. 지시서 01 의 표현을 이렇게 고친다:

```
틀림:  본 것 = 들인 것 + 겹친 것 + 버린 것   (파일 단위로 읽힘)
맞음:  본 것(조각) = 들인 것 + 겹친 것 + 버린 것
       그리고 조각이 하나도 안 나오는 파일도 「본 것」에 한 번 센다
```

# 3. 물음 — **자료를 현실적인 긴 글로 보강해라. 그래야 재진다**

네 판단이 옳다. 지금 자료로는 **문지기 뒤를 못 잰다** — 후보 3개가 전부 버려졌다.

문지기는 **「일하는 방법이나 도구 쓰는 법을 적어 둔 설명」**을 남기고, **과정 소음**
(진행 상황·인사·같은 말 반복)을 버린다. 그래서 반복형 시험 문장은 **버려지는 게 맞다.**

## 이런 걸 섞어라 (각 300~2000자)

```
① 설명글      「무엇을 어떻게 한다」가 든 글. 절차·설정·규칙 (남아야 한다)
② 결정 기록    「A 대신 B 를 골랐다. 까닭은 …」            (남아야 한다)
③ 잡담·인사    「확인했습니다」「진행하겠습니다」만 있는 글  (버려져야 한다)
④ 진행 로그    「1/10 …  2/10 …」                        (버려져야 한다)
⑤ 같은 글 두 장 (①을 그대로 복사, 이름만 다르게)          (겹침으로 잡혀야 한다)
⑥ 아주 긴 글  소제목 4개 이상, 3000자 이상                (2단 꺼내기 재는 자리)
```

★ **①②가 살고 ③④가 죽으면 문지기가 제 일을 한 것이다.** 그 비율을 적어 줘.
자료를 새로 만들어도 되고, 네가 쓰던 진짜 문서의 **사본**을 써도 된다(원본 말고).

# 4. 물음 — 창의 「엔진 — 글 모델 안 올라옴」

그 줄은 **서버에 물어본 결과**다. `--no-server` 로 켠 창은 서버가 없어서 늘 그 말이 뜬다.
CLI 흡수는 서버를 안 거치고 제가 직접 모델을 올리므로 **따로 논다** — 네가 본 그대로다.

```
그냥 켠 창(서버 있음) + models\ 에 gguf   → 「엔진 llama · 모델 1개 대기」 쪽으로 바뀐다
--no-server 로 켠 창                      → 늘 「글 모델 안 올라옴」  ← 이건 맞는 말이다
```
□ 그냥 켠 창에서 그 줄이 바뀌는지 봐 줘. 안 바뀌면 그건 결함이다.
