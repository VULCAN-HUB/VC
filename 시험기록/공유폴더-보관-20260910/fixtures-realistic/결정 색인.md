# 검색 색인 설계 결정
프로젝트의 문서 원본은 Markdown 파일로 유지하고 검색용 데이터베이스는 언제든 다시 만들 수 있는 파생 데이터로 취급하기로 결정했다. 모든 내용을 데이터베이스에만 저장하는 대안은 검색 속도 면에서 간단하지만, 사용자가 외부 편집기로 글을 고치기 어렵고 프로그램 오류가 원본 손실로 이어질 수 있다. 따라서 원본 파일의 수정 시각과 해시를 추적하는 색인 구조를 선택했다.
이 결정에는 변경 감지 지연과 동시 편집 충돌을 처리해야 하는 비용이 따른다. 파일 저장 이벤트가 짧은 시간에 여러 번 들어오면 마지막 안정 상태를 읽도록 대기 구간을 둔다. 읽기 도중 내용이 바뀌면 재시도하고 기존 색인을 먼저 삭제하지 않는다. 새 색인을 임시 트랜잭션에서 만든 뒤 성공했을 때 교체한다. 사용자가 삭제한 파일은 원본 디렉터리에서 확인한 뒤 색인에서 제거하며, 색인만 없다고 원본 파일을 지우는 역방향 처리는 금지한다. 승인 기준은 외부 편집 후 검색 결과 갱신, 재색인 후 원본 해시 보존, 전원 중단 후 일관성 회복이다. 이 기준을 통과하지 못하면 검색 성능 최적화보다 복구 절차 보완을 우선한다.
