# 문서 도구 검증 지침

## 입력과 경계 조건
문서 처리 도구의 입력 검증은 허용할 형식과 거부할 형식을 먼저 구분하는 데서 시작한다. 파일을 열기 전에 경로가 존재하는지, 읽을 수 있는지, 확장자와 실제 내용이 일치하는지 확인한다. 확장자만 보고 문서 종류를 결정하면 이름만 바뀐 파일을 잘못 처리할 수 있다. 문자 인코딩은 명시된 값을 우선하고, 값을 알 수 없을 때에는 판정 실패 사실을 기록한다. 읽을 수 없는 바이트를 조용히 버리면 문서 내용이 변하므로 사용자에게 원본을 보존한 상태에서 재시도 방법을 안내한다.
경계값 시험에서는 빈 파일, 공백만 있는 파일, 제목만 있는 파일, 앞머리 메타데이터만 있는 파일을 각각 준비한다. 이 네 종류는 화면에서 비슷해 보여도 파서와 저장 단계에서 다른 경로를 통과할 수 있다. 길이 제한이 있다면 제한보다 한 글자 적은 값, 같은 값, 한 글자 많은 값을 사용한다. 한글과 결합 문자, 이모지의 길이 계산 단위도 기록한다. 바이트 수와 화면상의 글자 수가 다르다는 사실을 모르면 경계 조건을 재현할 수 없다.
검증 결과는 통과와 실패만 적지 말고 어느 단계에서 어떤 규칙에 의해 분류됐는지 남긴다. 원본 파일 수와 생성된 조각 수를 분리하고 각 조각에 원본 상대경로와 위치를 연결한다. 내용이 비어 조각이 생성되지 않는 경우도 별도 상태로 집계한다. 최종 집계는 전체 입력 단위가 저장, 중복, 제외, 오류 중 정확히 한 분류에 속하는지 확인한다. 동일 입력을 다시 검사했을 때 분류가 달라지면 모델 설정이나 전처리 버전이 바뀌었는지 함께 비교한다.

## 저장과 중복 방지
저장 작업은 사용자가 다시 시도해도 결과가 중복되지 않도록 설계한다. 저장 버튼을 누르면 요청 식별자를 만들고 실제 파일 생성 전후에 처리 상태를 기록한다. 네트워크 응답이 늦다고 사용자가 버튼을 여러 번 누를 수 있으므로 화면에서 버튼을 잠그는 것만으로는 충분하지 않다. 처리 계층에서도 같은 요청을 다시 받았을 때 이전 결과를 돌려주는 규칙이 필요하다. 내용 기반 중복 검사와 요청 기반 중복 검사는 목적이 다르므로 각각의 판정 근거를 기록한다.
문서 내용의 해시는 공백 정규화 규칙을 명확히 정한 뒤 계산한다. 모든 공백을 제거하면 코드 예제나 표의 의미가 바뀔 수 있으므로 원본 전체 해시와 비교용 해시를 별도로 보관한다. 파일 이름이 다르지만 내용이 같은 경우와 제목은 같지만 내용이 다른 경우를 따로 시험한다. 중복 판정 때문에 사용자가 의도적으로 만든 사본이 사라지지 않도록 자동 삭제보다 후보 안내를 우선한다. 삭제 대신 이력 폴더로 옮기는 정책이라면 복원 시 이름 충돌을 어떻게 해결하는지도 정해야 한다.
원자적 저장은 같은 디렉터리의 임시 파일에 새 내용을 기록하고 쓰기가 완료된 뒤 이름을 교체하는 방식으로 검증한다. 저장 중 강제 종료를 모사할 때에는 테스트 사본만 사용한다. 재시작 후 기존 파일이나 새 파일 중 하나가 완전한 상태로 남아야 하며 두 파일이 모두 손상되면 실패다. 결과 보고에는 저장 전후 해시, 실제 파일 수, 중복 요청 횟수, 복구 여부를 기록한다. 저장 성공 안내가 나왔는데 파일이 없거나 내용이 잘렸다면 우선순위가 높은 결함으로 분류한다.

## 검색과 필요한 부분 읽기
검색 결과 목록은 사용자가 문서를 고를 수 있을 만큼의 정보만 전달한다. 제목과 짧은 요약, 소제목 목록, 전체 길이를 제공하고 본문 전체는 별도 요청으로 읽는다. 이렇게 나누면 작은 질문을 처리하기 위해 관련 문서 전체를 전송하는 낭비를 줄일 수 있다. 목록에 표시된 길이는 원본 본문과 같은 계산 규칙을 사용해야 한다. 요약의 길이를 전체 길이로 잘못 표시하면 사용자는 펼칠 문서의 크기를 예상할 수 없다.
소제목 기반 읽기에서는 요청한 소제목부터 다음 동급 이상의 소제목 직전까지를 선택한다. 하위 소제목을 포함할지 여부는 문서화하고 중첩된 구조로 검증한다. 같은 이름의 소제목이 두 번 나오면 첫 번째를 선택하는지 위치 식별자가 필요한지 명확히 해야 한다. 없는 소제목을 요청했을 때 본문 전체를 대신 반환하면 사용자가 예상한 범위를 넘어서므로 오류와 사용 가능한 목록을 돌려준다. 제목에 공백과 괄호가 있을 때에도 정확히 같은 글을 찾는지 확인한다.
검사 자료에는 각 구간에 서로 다른 고유 표식을 넣는다. 한 구간을 요청했을 때 그 표식은 있고 앞뒤 구간의 표식은 없어야 한다. 응답 크기는 문자 수와 바이트 수를 구분해 기록하고 목록 응답과 전체 본문 응답을 같은 자료에서 비교한다. 인증 없는 요청은 내용을 반환하지 않아야 한다. 인증 오류와 없는 문서 오류가 다른 상태로 구분되는지도 검사한다. 검색 정렬이 의미 기반이라면 제목이 정확히 같은 결과의 위치와 관련 없는 결과의 혼입을 별도로 평가한다.

## 외부 변경과 복구 검증
외부 편집기에서 파일을 수정하는 시험은 프로그램을 켠 채로 진행한다. 파일에 고유 표식을 추가한 시각을 기록하고 화면에서 표식이 보이는 첫 관측 시각을 남긴다. 두 관측 사이에 진단이나 재색인 명령을 실행하면 무엇이 갱신을 유발했는지 구분하기 어려우므로 자동 감지 시험 동안에는 별도 명령을 실행하지 않는다. 관측이 일정 간격으로 이루어지면 지연 시간을 단일 값으로 단정하지 말고 가능한 구간으로 보고한다.
외부에서 글을 바꾼 직후 프로그램에서도 저장하는 충돌 상황은 사본 창고에서만 재현한다. 어느 쪽 변경이 우선되는지 확인하고 사라진 변경을 이력에서 복원할 수 있는지 검사한다. 마지막 저장자가 이기는 정책을 쓰더라도 사용자에게 충돌 사실을 숨기면 수정 내용이 없어졌다고 느낄 수 있다. 최소한 변경 전 사본과 비교 가능한 이력을 남겨야 한다. 파일 감시기가 오류를 만나 중단됐을 때 다시 연결하는 절차도 필요하다.
복구 검증에서는 원본 Markdown을 보존한 상태에서 색인을 다시 만든다. 작업 전후 파일 해시 목록을 비교해 원본이 바뀌지 않았음을 확인한다. 색인 재생성이 실패하면 기존 검색 상태를 유지하는지, 빈 결과로 잘못 안내하는지 살펴본다. 결과에는 전체 항목 수, 연결 수, 빈 항목 수, 처리하지 못한 파일 목록을 포함한다. 미검증 항목은 통과로 세지 않는다. 문제가 재현되면 정확한 입력 사본과 실행 버전, 필요한 단계만 남겨 다음 배포본에서 같은 조건으로 비교한다.
