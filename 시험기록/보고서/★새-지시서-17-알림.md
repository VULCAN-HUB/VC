# 새 지시서 올렸다 — 17번 (v0.1.34)

**먼저 사과부터.** 지시서 16·17을 만들어 놓고 **네가 보는 자리에 안 올렸다.**
공유폴더가 내려가 있던 동안 릴리스 자산에만 올렸고, 그러면 네가 못 본다는 걸
「지시서 없다」는 말을 듣고서야 알았다. **없던 게 아니라 내가 안 보낸 것이다.**

지금은 세 자리 다 채웠다:

```
공유폴더        딴PC-시험-지시서-16.md · 17.md      ← 여기
깃허브 repo     tests/other-pc-test-guide-17.md    ← 본자리
릴리스 자산     guide-17.md
```

앞으로는 **깃허브 `tests/` 가 본자리다.** 공유폴더가 또 내려가도 거긴 남는다.

## 이번 판은 물건의 방향이 바뀌었다

```
지금까지:  사람이 쓰고, 사람이 찾는다
앞으로:    AI가 쓰고 관리하고, 사람은 찾기만 한다
```

**그래서 네 자리도 바뀐다.** 지금까지 너는 「사람이 적은 것이 되찾아지나」를 재 왔는데,
그건 네가 안 잊어서 **구조적으로 못 재는 자리**였다.
이번에 재는 것은 **「AI가 적어 놓은 것이 쓸 만한가」** — 원본과 항목을 나란히 놓고
견주는 일이고, 이건 **네가 사람보다 훨씬 잘한다.**

자리가 있다(31개 썼는데 파일은 29개였다). v0.1.34 에서 고쳤다.

## 만들면서 내가 먼저 만난 것들 — 지시서에 다 적어 뒀다

- **작은 모델에는 물음을 적게 줘야 판단을 한다.** 승격 물음 아홉 개를 얹었더니
  30개 중 30개를 통과시키고 **내 지시문을 그대로 항목으로 냈다.**
- **요약을 시켰더니 소설을 썼다**(「시작합니다」→「완료하고」). 그래서 요약을 껐다.
  **네게 「지어낸 말을 찾아 달라」고 하려던 결함을 내가 먼저 만났다.**
- **죽은 문지기가 「다 통과」로 보였다** — 1058 조각이 1초에 전부 통과했는데
  셈만 보면 멀쩡했다.

## 이번에 네가 답해 줄 것 중 제일 큰 것

**「이 제목으로 몇 달 뒤에 찾을 수 있겠나」.**

제목을 원문에서 뽑아 쓰니 **틀릴 수는 없는데 쓸모없을 수는 있다.**
여기서 실제로 이런 게 나왔다 — 「Context」 「금지」 「3) ★ 개인 마이크로소프트 계정으로…」.

**「이 제목으로는 못 찾겠다」 싶은 것을 그대로 적어 달라.** 그게 이번 판의 본론이다.

그리고 지난 지시서에서 물은 **「여기서는 못 잰다」 목록**도 아직이면 이번에 부탁한다.
네가 구조적으로 못 재는 자리를 알아야, 내가 못 받을 답을 계속 묻지 않는다.
