# 2. ★★ 릴리스 시험에서 나온 결함 둘

## D-01 (Critical) — 같은 폴더를 다시 흡수하면 **사본이 또 생긴다**

```
1. 글 2장 폴더를 --흡수 --쓴다        → 2장 들어온다 · 항목 2
2. 같은 폴더를 --흡수 (미리보기)       → 겹친 것 0 · 들인 것 2    ← 여기서 이미 틀렸다
3. 같은 폴더를 --흡수 --쓴다          → 「제목 (제목).md」 2장이 더 생긴다 · 항목 4
```

**색인은 앞선 2장을 알고 있다** (`--doctor` 항목 수 2). **자료가 없어서가 아니라 안 본다.**

★★ **이건 네 기록에서 이미 터진 그 결함이다.**
v0.1.72 알림에 「3183장 중 본문이 똑같은 뭉치 **388개** · 치울 것 388장 (**12.2%**)」,
원인은 「같은 글이 두 나무에서 흡수됐다」고 적혀 있다.

→ **`--사본치우기` 는 증상을 치우는 기능이고, 원인은 아직 살아 있다.**
  지금 치워도 **다시 흡수하면 다시 쌓인다.**

※ 곁가지 : 사본 이름이 `제목 (제목).md` 로 **제목을 두 번 적는다.**

## D-02 (Major) — 본문이 비어 같아지는 파일이 여럿이면 **하나가 셈에서 사라진다**

```
본문이 비는 파일 3개를 한 폴더에 두고 --흡수
  → 싼 문지기 — 본 것 2 · 들인 것 0 · 겹친 것 0 · 버린 것: 빈 파일 2

  파일은 3개인데 본 것이 2다.  2 + 0 + 0 = 2 ≠ 3
  (0바이트 / 앞머리만 / 이진 쓰레기 — 셋 다 본문이 빈다)

셋을 하나씩 따로 넣으면 각각 본 것 1 로 제대로 세어진다  ← 합쳤을 때만 사라진다
```

사라지는 게 버릴 글뿐이라 **자료 손실은 없다.** 다만
**「본 것 = 들인 것 + 겹친 것 + 버린 것」이라는 이 도구의 셈 약속이 깨진다.**
「내 파일을 다 봤나」에 틀린 답을 준다.

## 결함 유출 — 둘 다 시스템 단계에서 처음 잡혔다

| 주입 \ 발견 | 리뷰 | 단위 | 통합 | 시스템 |
|---|---|---|---|---|
| 설계 | | | | **D-01** |
| 코딩 | | | | **D-02** |

**앞 단계를 하나도 안 거쳤다.** 특히 D-01 은 **설계에서 주입되어 네 기록 12.2% 를
이미 오염시킨 뒤** 여기서 잡혔다. 흡수가 이 제품의 중심인데
**「같은 것을 두 번 넣는다」 케이스가 어느 단계에도 없었다.**
v0.1.64 때 「제일 흔한 길(그냥 켜기)을 아무도 안 밟고 있었다」와 **같은 꼴**이다.
