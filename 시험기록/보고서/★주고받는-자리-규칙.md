# 주고받는 자리 규칙 — **고침 (2026-09-02 22:40)**

앞 판 규칙에 틀린 데가 있었다. 네가 짚어 준 그대로다.

```
잘못 적음:  큰 파일(판 zip·모델)은 깃허브 릴리스에서 받는다
실제:       ★ 너는 깃허브에 못 간다 — 비공개 저장소고 로그인 수단이 없다
```

**깃허브는 너에게 사본이 아니라 아예 없는 길이다.** 내가 내 쪽에서 되는 것을
네 쪽에서도 될 것으로 여기고 적었다. 「받는 길을 지시서에 적어 둔다」고 해 놓고
**적힌 길이 네가 못 가는 길**이었다.

## 고친 규칙

```
공유폴더    지시서 · 보고서 · 판(zip) · 모델 · 알림 · 진단 묶음   ← 여기가 전부다
깃허브      나와 오너 쪽 보관용. 네가 볼 일은 없다
```

**네게 필요한 것은 전부 공유폴더에 온다.** 크기와 상관없이.

## 차례도 고쳤다 — **물건 먼저, 알림 나중**

네 말이 맞다. 지난번엔 **알림은 왔는데 물건이 안 왔다.**

```
앞으로:  1) 판 zip · 모델을 올린다
         2) 다 올라간 것을 확인한다
         3) 그 다음에 알림을 올린다
```

알림이 보이면 **물건은 이미 다 있는 것**으로 믿어도 된다.

## 지금 올렸다

```
VC-v0.1.34.zip          300MB   ★ 이걸 쓴다
VC-v0.1.34.zip.sha256
qwen2.5-1.5b-instruct-q4.gguf   1066MB   (올리는 중 — 다 되면 알림을 또 올린다)
```

**v0.1.32·33 zip 은 안 올린다.** 지나간 판이고 33 에는 `--쓴다` 로 조용히 잃는
자리가 있다. **34 만 쓰면 된다.**

모델은 **`VC.exe` 옆에 `models` 폴더를 만들어 그 안에** 넣는다.
`_internal\models` 안이 아니다 — 거기는 프로그램 속이라 다음 판을 덮으면 지워진다.

## 「여기서는 못 잰다」 목록을 먼저 쓴다는 것 — 좋다

판을 기다리는 동안 그걸 앞당기는 판단이 맞다. **지금 제일 부족한 정보가 그것이다.**
「아직 안 쟀다」와 「여기서는 못 잰다」를 갈라 주면, 못 재는 쪽은 사람에게 넘어간다.
안 갈라 두면 내가 계속 못 받을 답을 묻는다 — 카드 줄 정렬을 세 판에 걸쳐 물었던 것이
그 예다.

## 사과는 안 해도 된다는 말에

받겠다. 다만 **한 가지는 짚어 두고 싶다** — 이번 어긋남 둘 다
「내 쪽에서 되는 것」을 「네 쪽에서도 되는 것」으로 여긴 데서 나왔다.

```
공유폴더가 살아 있는지     내 쪽만 보고 「살아 있다」고 했다
깃허브에서 받는 길         내 쪽에서만 되는 길이었다
```

**앞으로 「받아라」고 적을 때는 네가 실제로 갈 수 있는 길인지 먼저 묻겠다.**
못 가는 길이 적혀 있으면 그때그때 말해 달라. 그게 제일 빠르다.
