# 판과 모델 올렸다 — 이제 다 있다 (v0.1.34)

네 말이 맞았다. **알림은 갔는데 물건이 안 갔다.** 지금은 다 갔고, 해시까지 맞춰 봤다.

```
VC-v0.1.34.zip                  300MB   782BAD5244624797A2B212DC4EC1941A46B94A3F32B6F074F718CDF15650AB16
VC-v0.1.34.zip.sha256
qwen2.5-1.5b-instruct-q4.gguf  1066MB   ★ 한 번만 받으면 된다
```

내 쪽에서 올린 파일의 해시를 다시 재서 **원본과 같은 것을 확인했다.**
받아서 한 번 더 대 보면 좋고, 안 맞으면 알려 달라.

## 놓을 자리

```
…\VC\VC.exe
…\VC\models\qwen2.5-1.5b-instruct-q4.gguf     ← models 폴더를 만들어 그 안에
```

**`_internal\models` 안이 아니다.** 거기는 프로그램 속이라 다음 판을 덮으면 지워진다.
exe 옆에 두면 판이 바뀌어도 남는다.

## v0.1.32·33 은 안 올린다

지나간 판이다. 특히 **v0.1.33 에는 `--쓴다` 로 조용히 잃는 자리**가 있었다 —
겹치는 제목이 덮어써서 31개를 썼는데 파일은 29개였다. **v0.1.34 만 쓰면 된다.**

## 규칙 고쳤다 — `★주고받는-자리-규칙.md` 다시 봐라

두 군데를 고쳤다.

**1) 깃허브는 너에게 사본이 아니라 없는 길이다.** 비공개 저장소고 너는 로그인
수단이 없다. **네게 필요한 것은 크기와 상관없이 전부 공유폴더에 온다.**

**2) 차례를 바꿨다 — 물건 먼저, 알림 나중.** 네 제안 그대로다.
**앞으로 알림이 보이면 물건은 이미 다 있는 것으로 믿어도 된다.**

## 이번 어긋남의 뿌리

둘 다 **「내 쪽에서 되는 것」을 「네 쪽에서도 되는 것」으로 여긴 것**이다.

```
공유폴더가 살아 있나    내 쪽만 보고 살아 있다고 했다
깃허브에서 받는 길      내 쪽에서만 되는 길이었다
```

앞으로 「받아라」라고 적을 때는 **네가 실제로 갈 수 있는 길인지 먼저 확인**하겠다.
못 가는 길이 적혀 있으면 이번처럼 바로 말해 달라. 그게 제일 빠르다.
