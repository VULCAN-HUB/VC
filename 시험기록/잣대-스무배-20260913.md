# 20년치 규모에서 버티나 [잰 것, 2026-09-13]

오너 창고가 2,800장이다. 하루 세 장이면 20년에 2만 장이 된다. 재 봤다.

## 찾은 결함 — 쓰기가 O(장수)였다

같은 날 넣은 막이(대소문자만 다른 제목 가르기)가 **새 글마다 폴더 전체를 훑고** 있었다.

```
2,000장   17.3ms/장
19,000장대 785ms/장   ← 45배
2만 장 쓰기 1,563초
```

`exists()` 로 먼저 거르게 고쳤다(윈도우는 대소문자를 안 가려 늘 True 를 준다 —
겹칠 때만 폴더를 훑으면 된다). **2만 장 쓰기가 1,563초 → 154초(7.7ms/장)** 로 돌아왔다.
자체점검이 이 자리를 지킨다: 300장 든 폴더에서 새 글 자리 찾기가 10ms 를 넘으면 터진다.

## 2만 장 값 [잰 것, 고친 뒤]

```
처음부터 훑기 8초 · 색인 57MB · 파일 20,001장
낱말 하나 119ms · 낱말 둘 131ms · 좁히기 101ms · 빼기 115ms
제목만 76ms · 하나라도 131ms · 태그 32ms · 그물 183ms · 외딴 세기 41ms
```

사람이 못 느끼는 범위다. 실무 창고(2,820장)에서는 모두 40ms 아래다.

## 계산으로 본 것 [잰 것 — 벡터 곱만 떼어 잼]

| 장수 | 뜻 곱 한 번 | 벡터 메모리 |
|---:|---:|---:|
| 2,820 | 0.7ms | 8MB |
| 20,000 | 4.4ms | 58MB |
| 100,000 | 27.9ms | 292MB |

한 장에 벡터 3,072바이트(본문 768 + 제목 768, float32)다. **10만 장까지는 통째로 곱해도 된다** —
근사 색인(HNSW 등)을 들일 이유가 아직 없다.

## 딴 것들 [잰 것]

- 이력: 한 장 942바이트 · 하루 10판이면 20년에 **65MB**. 안 자른다
- 학습 로그: 한 줄 170바이트 · 하루 200줄이면 20년에 213MB, 읽기는 9천 줄에서도 0.1ms. 안 자른다
- 첨부 300장 쓰기 0.2초 · 이름으로 찾기 1ms
- 화면 그물은 400장 상한이 이미 있다(물리 계산이 장수에 비례한다)
