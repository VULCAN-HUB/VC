# VC v0.1.2 재시험 — 지시서 3

2차 보고서 최고였다. **「방향키는 팝업이 받는다」** 한 줄이 결정적이었다 —
그걸로 `[[` Esc 고침이 헛다리였다는 걸 알았다. 손댄 코드가 아예 안 돌고 있었다.

「본문이 저장 안 된다」도 그쪽 관측 다섯 개(제목은 반영 / 본문만 실패 / 오류 없음 /
`.이력` 0개 / 그래서 「지난 판」 확인 불가)가 **한 원인으로 전부 설명됐다.**

## 무엇이 원인이었나 (시험할 것을 알려면 알아야 한다)

**제목을 바꾸면 파일이 옮겨진다.** 그런데 프로그램이 「지금 연 파일」 자리를
옛 경로로 계속 들고 있었다. 그래서 그 뒤 저장은 없는 파일을 찾다가
**아무 말 없이 돌아섰다.**

즉 **이름을 바꾼 항목만** 저장이 안 됐다. 그쪽이 시험한 「빈것셋」은
`Ctrl+N` 으로 만들고 제목을 친 것이라 정확히 그 경우였다.

> **`Ctrl+N` → 제목부터 치기가 가장 흔한 길이다.** 새로 받는 사람은 첫 글부터 잃는다.
> 「지난 판」·할 일 표시가 막혀 있던 것도 전부 이것 하나였다.

## v0.1.2 에서 바뀐 것

| # | 무엇 | 어떻게 고쳤나 |
|---|---|---|
| 1 | **본문이 저장 안 됨** | 이름을 바꾸면 연 파일 자리도 같이 옮긴다 |
| 2 | `[[` 목록 Esc | 목록(팝업)에 **직접** 거름망. 글상자 쪽은 키가 안 지난다 |
| 3 | 밖에서 고친 글이 화면에 안 옴 | `연/월` 폴더까지 지켜본다. 뿌리만 보고 있었다 |

## 1) ★ 최우선 — 이름 바꾼 뒤 저장 (1차·2차 다 막혔던 자리)

**2차에 실패한 그 순서 그대로** 한다.

1. `Ctrl+N`
2. **제목을 친다** — `첫 글` (이 단계가 파일을 옮긴다. 여기가 함정이었다)
3. 「고치기」
4. 본문에 `가나다라마` 치기
5. 「읽기」 클릭

확인:

```powershell
$N = "$env:VC_DATA\data\notes"
Get-ChildItem $N -Recurse -Filter "첫 글.md" | Select-Object FullName, Length
Get-Content (Get-ChildItem $N -Recurse -Filter "첫 글.md").FullName -Encoding UTF8
```

| 결과 | 뜻 |
|---|---|
| 파일 끝에 `가나다라마` 가 있다 | **통과** |
| 93바이트 앞머리만 있다 | 실패 — 2번(제목 치기) 하고 나서 크기를 다시 재 달라 |

### 1-1) 같은 것을 세 갈래로 더

원인이 하나였는지 확인하려면 **이름을 안 바꾼 경우도** 봐야 한다.

| 갈래 | 순서 | 기대 |
|---|---|---|
| A | `Ctrl+N` → **제목 안 바꾸고** 바로 본문 쓰고 저장 | 저장돼야 함 |
| B | 이미 있는 항목(1-2에서 만든 「첫 글」)을 열어 본문에 한 줄 **덧붙이고** 저장 | 저장돼야 함 |
| C | 제목을 **두 번** 바꾸고(`첫 글`→`둘째 글`→`셋째 글`) 본문 쓰고 저장 | 저장돼야 함 |

C 가 중요하다 — 한 번만 고쳤을 수도 있어서다.

### 1-2) 「지난 판」 — 2차에 확인 못 했던 것

「첫 글」을 **세 번 고쳐 저장**한다(내용을 매번 다르게).

- 카드 위에 **「지난 판」 콤보**가 나타나야 한다
- 이력 파일도 봐라:

```powershell
Get-ChildItem "$N\.이력" -Recurse -Filter *.md | Select-Object Name, Length
```

콤보에서 옛 판을 골라 되돌려 본다. **확인창 단추가 「되돌린다 / 그만둔다」** 인지도 봐 달라.

> 저장 사이 간격이 5분 미만이면 이력을 한 판으로 묶는다(설계 그대로).
> 이력이 1~2개만 나와도 정상이다. **0개면 실패다.**

### 1-3) 할 일 표시

본문에 이렇게 넣고 저장:

```
- [ ] 첫째
- [ ] 둘째
```

읽기 모드에서 네모를 클릭 → 체크로 바뀌고, **파일에도** `- [x]` 로 들어가야 한다.
(이것도 같은 원인으로 막혀 있었다)

## 2) `[[` 목록 Esc

「고치기」에서 `[[` 치고 목록이 뜬 상태에서:

| 누름 | 기대 |
|---|---|
| **Esc 한 번** | 목록이 닫힌다 |
| 그 상태에서 다시 Esc | 이번엔 고치기에서 나가도 된다(카드가 닫히거나) |
| 아래방향키 | 예전처럼 선택이 움직인다 (**이건 계속 돼야 한다**) |

2차에 그쪽이 방향키로 확인해 준 그 방법 그대로 해 달라 — 그게 결정적이었다.

## 3) 밖에서 고친 글이 화면에 오나

VC 를 **켜 둔 채로**, 항목 하나를 화면에 열어 둔 상태에서:

```powershell
$f = (Get-ChildItem $N -Recurse -Filter "첫 글.md").FullName
Add-Content $f "`n밖에서 덧붙인 줄" -Encoding UTF8
```

**2초쯤 뒤** 열려 있는 카드에 그 줄이 나타나야 한다.

세 경우를 갈라 봐 달라:

| 경우 | 어떻게 | 기대 |
|---|---|---|
| 읽기 모드로 열어 둠 | 위 명령 | 화면에 나타난다 |
| **고치기 모드로 열어 둠** | 같은 명령 | **안 덮어써야 한다.** 「밖에서도 고쳤어」 안내가 뜨거나, 최소한 치던 글이 안 사라져야 함 |
| 안 열어 둔 항목 | 다른 파일을 고침 | 그 항목을 열면 새 내용 |

가운데가 중요하다 — **치던 글을 밖에서 온 내용이 덮으면 그게 더 나쁜 버그다.**

## 4) 되짚기 — v0.1.1 에서 통과했던 것이 그대로인가

고치면서 망가뜨렸을 수 있다. **빠르게만** 확인해 달라.

| 확인 | 기대 |
|---|---|
| `이미지 다듬는 법` 검색 | 안 죽는다. 1등 = 사진 보정 순서 |
| 빈 항목 3개 만들고 아무거나 검색 | 빈 항목이 결과에 없다 |
| 돋보기 아이콘 클릭 | 검색 실행 |
| 빈 화면에 `＋ 새 항목` | 보인다 |
| 지우기 확인창 | 「지운다 / 그만둔다」 |

씨앗 8개가 필요하면 지시서 2의 것을 그대로 쓰면 된다.

## 5) 막 굴리기 — 이번엔 **저장을 섞어서**

1차·2차의 난타는 안 죽는 것만 봤다. 이번엔 **글이 안 사라지는지**를 본다.

VC 켜 둔 채로:

```powershell
# 밖에서 흔드는 동안 화면에서는 글을 계속 쓴다
1..40 | ForEach-Object {
  Set-Content (Join-Path $N "난타-$_.md") "내용 $_" -Encoding UTF8
  Start-Sleep -Milliseconds 250
}
```

돌아가는 동안 화면에서 **항목 만들기 → 제목 바꾸기 → 본문 쓰기 → 저장**을
대여섯 번 반복한다. 끝나고:

- 방금 쓴 글이 **전부 파일에 들어갔나** (하나라도 비면 그 제목을 적어 달라)
- `.tmp` 0개인가
- 화면 항목 수 = 실제 `.md` 수인가

```powershell
Get-ChildItem $N -Recurse -Filter *.tmp
(Get-ChildItem $N -Recurse -Filter *.md | Where-Object { $_.FullName -notlike "*\.이력\*" }).Count
```
