# VC v0.1.33 — 물건의 방향이 바뀌었다

먼저 알려 줄 것이 있다. **이 물건이 무엇인지가 오너에 의해 다시 정해졌다.**
지금까지 우리가 시험해 온 것과 앞으로 시험할 것이 달라진다.

```
옵시디언:  사람이 쓰고, AI가 돕는다
VC (지금): 사람이 쓰고, 사람이 찾는다
VC (앞으로): AI가 쓰고 관리하고, 사람은 찾기만 한다
```

먼 목표는 스마트글래스다 — 보는 것·듣는 것·착용자가 하는 말을 담아 두고 AI가
갈라서, 일정·업무·회의 같은 **그냥 흘려보내던 것**을 항목으로 남긴다.
장비가 없어 소리는 뒤로 미뤘고, **먼저 PC 안에 이미 있는 자료부터 들인다.**

## 이게 너에게 뜻하는 것

**앞으로 항목은 대부분 네가 안 쓴 것이 된다.** 시험할 것도 바뀐다 —
「내가 적은 게 찾아지나」가 아니라 **「AI가 적어 놓은 것이 쓸 만한가」**다.

---

## 이번 판에 새로 생긴 것 둘

### 1) 흡수 (`ingest.py`) — 싼 문지기

폴더를 훑어 조각내고, **읽지 않고도 아는 쓰레기**를 걷어낸다.
너무 짧은 것 · 기호 덩어리 · 거의 코드 · 같은 글.

**원본은 안 옮긴다.** 파일이 그대로 원본층이고 항목은 그 자리와 줄 번호만 지고
다닌다. 옮기면 같은 글이 두 벌이 되고 밖에서 고쳤을 때 어느 쪽이 참인지 모른다.

여기서 잰 것(오너 PC, 실제 자료):

```
옵시디언 1316 · 기록 2886 · 프로젝트 2843  →  모두 7045 조각
기록 폴더는 본 것의 34%가 같은 글이었다 (2816/8378)
```

### 2) 문지기 (`gate.py`) — 비싼 쪽

싼 문지기만으로 모자란 것이 **숫자로 나왔다** — 남은 7045개 중 기록 몫 2886개는
대부분 「파일 읽음」 「검사 통과」 같은 과정 소음이다. 그건 읽어 봐야 안다.

모델이 조각을 읽고 **남길지 정한다.** 물음은 오너 볼트에서 몇 달 굴러 검증된
승격 게이트를 옮기되 **일상 쪽을 넣었다** — 볼트 것은 다섯 다 「일」 쪽이라
그대로 쓰면 「치과 3시」도 「우유 사야 한다」도 떨어진다.

★ **못 알아들으면 막지 않고 남긴다.** 원본 파일은 그대로 있으니 잘못 남겨도
없어지는 것은 없지만, 잘못 막으면 사람은 그런 게 있었다는 것조차 모른다.

### ★★ 여기서 큰 것을 배웠다 — 두 번

**(1) 작은 모델에는 물음을 적게 줘야 판단을 한다.**

처음에 승격 물음 아홉 개 + JSON 다섯 칸을 한 번에 얹었더니 이렇게 나왔다:

```
30개 중 30개 통과 · 막은 것 0
[일정] 일상 쪽 / "날짜나 기한이 붙어 있는가"   ← 내 물음을 그대로 항목으로 냈다
```

**판단 대신 지시문을 흉내 냈다.** 「남긴다/버린다」 한 낱말만 요구하니 베낄 것이
없어져 그제야 갈랐다 — 같은 서른 개가 12/18 로 갈리고 조각당 2.8초가 0.3초가 됐다.

**(2) 그리고 요약을 시켰더니 소설을 썼다. 그래서 요약을 껐다.**

```
원문: 목록은 LIMIT 유지, 통계만 GROUP BY 로 분리합니다
지음: "최근에 데이터 분석을 해본 적이 있다"        ← 통째로 지어냄

원문: SQLite 전환을 시작합니다
지음: "SQLite 전환 작업을 완료하고…"               ← 시작을 완료로 뒤집음
```

**네게 찾아 달라고 하려던 결함을 내가 먼저 만났다.** 그래서 사다리 첫 칸으로
돌아가 물었다 — 짓는 일이 꼭 있어야 하나?

| 짓기가 주는 것 | 실제 |
|---|---|
| 짧은 제목 | 조각에 이미 표제가 있다 |
| 간추린 몸 | **원문이 더 정확하고 찾기에도 더 좋다**(글자가 많아야 걸린다) |

**지금은 안 짓는다.** 몸은 원문 그대로, 제목은 원문에서 뽑는다 —
**뽑은 제목은 틀릴 수가 없다.** 제대로 요약하는 모델이 생기면 켤 수 있게
손잡이(`지어줄까`)만 남겨 뒀고, 켜더라도 **지은 글이 원문과 낱말이 안 겹치면
버리고 원문으로 되돌린다.**

---

## 규모를 재 봤다 — 그리고 **내가 한 번 틀렸다**

「이음 다시 짓기가 n²라 수만 개에서 벽」이라고 적었는데, 재 보니 **이유가 틀렸다.**

```
  529개  0.00초          7045개  0.38초  판 0.18GB
20000개  3.41초 판 1.5GB   50000개  판 9.3GB → 못 한다
```

시간이 아니라 **점수판을 통째로 램에 올리는 것**이 벽이다. 고치는 값도 훨씬 싸다 —
판을 토막 내서 훑으면 된다. **7045개는 지금 그대로 아무 문제 없다.**

> 처음에 float16 으로 재서 529개조차 2분을 넘겼는데, 코드를 열어 보니
> **곱하기 전에 float32 로 올리고 있었다.** 내가 프로그램이 안 하는 짓을 재고 있었다.
> 재는 것과 코드를 읽는 것을 둘 다 해야 한다.

## 0) 받기 — ★ 이번엔 **하나 더** 받는다

```
VC.zip / VC.zip.sha256                    늘 받던 것
qwen2.5-1.5b-instruct-q4.gguf   1066MB    ★ 이번에 처음. 한 번만 받으면 된다
```

문지기가 쓰는 모델이다. **zip 에 안 담았다** — 1GB짜리를 판마다 다시 받게 하는 것은
값이 안 맞는다. 한 번 받아서 아래 자리에 두면 다음 판부터는 그냥 쓴다.

```
VC.exe 가 있는 폴더에 models 폴더를 만들고 그 안에 넣는다
   …\VC\VC.exe
   …\VC\models\qwen2.5-1.5b-instruct-q4.gguf     ← 여기
```

`_internal\models` 안이 아니다. **exe 옆에 새로 만든다** — 거기는 프로그램 속이라
다음 판을 덮어씌우면 지워진다.

**모델이 없으면 `--흡수` 는 아무것도 안 쓰고 그 사실을 알리고 멈춘다.**
문지기 없이 쌓으면 과정 소음이 그대로 항목이 되기 때문이다.

> 이 자리를 못 찾는 결함을 **보내기 전에 잡았다.** 구운 exe 로 한 번 돌려 봤더니
> 「models/ 에 글 모델이 없다」로 멈췄다 — `__file__` 이 구운 뒤에는 `_internal`
> 안을 가리켜서 두 칸 올라가면 엉뚱한 자리였다.
> **검사 열셋이 다 통과해도 구운 것으로 한 번 돌려 보는 것과는 다르다.**

기록 자리 그대로. 529개 위에 이어 간다.

## 1) ★★ 이번 판의 본론 — **AI가 쓴 항목이 쓸 만한가**

네 PC 안 아무 폴더나 골라 흡수를 돌려라(문서·프로젝트·기록 무엇이든).

```powershell
.\VC.exe --흡수 "C:\고른\폴더"     # 들일 것만 세어 보고 안 쓴다
.\VC.exe --흡수 "C:\고른\폴더" --쓴다
```

**`--쓴다` 없이 먼저 돌려라.** 몇 개가 들어올지 보고 나서 결정한다.

재 줄 것:

| | |
|---|---|
| 셈 | 본 것 · 들인 것 · 겹친 것 · 버린 이유별 수 |
| 문지기 | 남긴 것 · 버린 것 · **못 알아들은 것 몇 %** |
| 시간 | 조각당 몇 초 |

여기서 잰 값 — **구운 exe 로**, 오너 볼트의 한 폴더:

```
싼 문지기   104 → 86     짧은 것 14 · 겹친 것 4
비싼 문지기  86 → 31     ★ 65%를 걸러냈다 · 못 알아들음 0
135초 · 조각당 1.30초
```

★ **조각당 1.3초다.** 상자에 담은 엔진이 CPU 전용이라(그래야 5.7MB) 그렇다.
1000 조각이면 20분, 7000 조각이면 두 시간 반이다. **한꺼번에 많이 넣지 마라** —
처음엔 폴더 하나, 몇백 조각짜리로 재 봐라.

★ **「못 알아들은 것」 비율이 제일 중요하다.** 그게 크면 문지기가 일을 하는 게
아니라 그냥 다 통과시키고 있는 것이다. **20%를 넘으면 그 자체가 결함 보고다.**

### 1-1) ★★★ 그리고 이건 네가 제일 잘할 수 있는 일이다

들어온 항목 **스무 개를 골라 사람 대신 채점해 달라.** 표로:

| 제목 | 갈래 | 몸이 원문과 같나 | 이 제목으로 찾을 수 있겠나 |
|---|---|---|---|

몸은 원문 그대로여야 한다 — **한 글자라도 다르면 그것부터 적어 달라.**
지금은 지어내는 길을 껐으니 다를 수가 없는데, 다르다면 내가 못 본 길이 있는 것이다.

**제목 쪽이 이번의 진짜 물음이다.** 표제가 없는 조각은 첫 문장을 제목으로 쓰는데,
그게 「몇 달 뒤에 이걸 찾을 때 떠올릴 말」인지는 재 봐야 안다.
**「이 제목으로는 못 찾겠다」 싶은 것을 그대로 적어 달라.**

## 2) 막은 것이 옳게 막혔나

문지기가 막은 것 중 **열 개를 봐라.** 막힌 게 맞는지.

**★ 「이건 남겼어야 했다」가 하나라도 있으면 그게 제일 값진 결과다.**
지금 문지기는 「모르겠으면 남긴다」로 기울여 놨는데, 그래도 막힌 것이 아까우면
물음이 잘못 지어진 것이다.

## 3) 늘 하던 것 (짧게)

```powershell
.\VC.exe --재보기
.\VC.exe --찾기점수      # 스무 물음은 손대지 마라
```

지난 판: `1등 16 · 3등 안 17 · 목록 밖 3 · 0.3초`

**흡수로 항목이 크게 늘면 찾기 점수가 떨어질 수 있다.** 후보가 늘면 흐려지는 것이
보통이다. 떨어졌으면 그것도 결과다 — 얼마나 떨어졌는지가 다음 판의 재료가 된다.

## 4) 지난 판 셋 (오너가 잡은 것)

|  | 통과 기준 |
|---|---|
| 자전 | 커서를 그래프 **빈 자리**에 두고 손 떼도 **계속 돈다** |
| 자전 | 항목 **위에** 두면 멈추고, 6초쯤 지나면 다시 돈다 |
| 표식 | 창 크기를 바꿔 로고가 옮겨갈 때 **네모가 안 남는다** |

## 5) 마무리

```powershell
.\VC.exe --report
```

## 한마디

**물건이 바뀌었으니 네 자리도 바뀐다.**

지금까지 너는 「사람이 적은 것이 되찾아지나」를 재 왔는데, 그건 네가 안 잊어서
구조적으로 못 재는 자리였다. **AI가 적은 것이 쓸 만한가는 다르다** —
그건 원본과 항목을 나란히 놓고 견주는 일이고, **네가 사람보다 훨씬 잘한다.**

특히 **원문과 나란히 놓고 견주는 일**은 네가 제일 잘한다. 사람은 원본 스무 개를
다시 읽지 않는다.

그리고 이번에 내가 겪은 것을 그대로 적어 둔다 — **네게 찾아 달라고 하려던 결함을
내가 먼저 만났다.** 만들면서 한 번 돌려 보지 않았으면 「지어낸 말이 있나」를
물어 놓고 소설 쓰는 문지기를 보냈을 것이다.
**보내기 전에 한 번 돌려 보는 것**이 지시서를 잘 쓰는 것보다 값졌다.
