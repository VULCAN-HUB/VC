# VC v0.1.14 — 벡터 셋의 끝

**네 짐작이 맞았다.** 그리고 네가 「카운터가 틀린 것 같다」고 덧붙여 준 것이 두 번째 버그였다.

---

## 무엇이었나

### 1) 벡터가 빠진 채로 남는 항목 — 네 짐작대로다

본문이 있는데 벡터가 없고 「아직 못 만든 것」에도 안 잡히면, 그 항목은 **영영 뜻 검색에서
빠진다.** 사람은 알 길이 없다. 벡터 표에 칸이 없던 판(v0.1.10·11)을 쓰는 동안 만들어진
항목들이 그렇게 남았다.

**이제 켤 때마다 스스로 되살린다.** 그런 항목을 찾아 「다시 만들 것」으로 표시한다.
색인은 다시 만들 수 있는 것이라 표시만 되돌리면 뒤에서 알아서 채운다.

### 2) 「본문이 빈 항목」 카운터 — 네가 잡은 것

**SQLite 의 `trim()` 은 공백만 떼고 줄바꿈은 안 뗀다.** 앞머리 뒤에 빈 줄만 있는 항목이
「비지 않았다」로 세어졌다. 네가 파일을 직접 세어 보고 「0 인데 실제로는 하나 있다」고
짚어 준 그것이다.

**값이 0 으로 나온 덕에 결론이 더 또렷해졌다는 네 말이 맞다** — 그러면서도 「그 카운터를
그대로 두면 다음에 진짜 빈 항목이 생겼을 때 못 잡는다」고 덧붙인 것이 이 고침을 만들었다.
답이 맞게 나왔다고 셈법까지 맞은 것은 아니다. 그걸 갈라 본 것이 좋았다.

### 3) `--색인다시`

```powershell
.\VC.exe --색인다시
```

색인을 통째로 버리고 다시 만든다. **기록(`.md`)은 안 건드린다.**
켤 때 저절로 고치기도 하지만 손으로 시킬 길도 있어야 한다.

## 1) ★ 벡터 셋이 채워지나

띄우고 잠깐 두었다가:

```powershell
.\VC.exe --doctor
```

| 값 | 통과 기준 |
|---|---|
| 항목 수 | 500 |
| 뜻 벡터 수 | **500** (또는 499 — 아래 참고) |
| 아직 못 만든 벡터 | 0 |
| **본문이 빈 항목** | **1** (0 이면 카운터 고침이 안 먹은 것) |

「본문이 빈 항목」이 1 이면 벡터는 **499** 가 맞다. 빈 항목은 일부러 벡터를 안 만든다.
즉 **499 + 빈 것 1 = 500** 이면 딱 맞는 것이다.

셋이 그대로 모자라면 `--색인다시` 를 돌리고 다시 봐 달라. 그래도 안 되면 알려 달라.

## 2) 지시서 13 에서 못 끝낸 것

시계 때문에 미뤄졌던 것들이다. v0.1.14 로 하면 된다.

- **닫는 길 다섯** (닫기 단추 · 빈 곳 · 곁에 띄운 상태 · Esc)
- 되면 **500개에서 그래프 제목 개수**
- **덧붙이기 넷** (「학교에 안 갔다」가 무엇을 적었는지 말해 주나 · 무르고 · 「물어보기」)
- 「아래 띠 말이 어색하던 것」을 **v0.1.14 로 다시 재서** 견주기
  (v0.1.12 값은 이미 받았다 — 8개 밖. 판이 달라졌으니 갈라 적어 달라)

## 3) 실사용 계속

## 한마디 — 이번에 네가 한 것 중 제일 값진 것

**「값이 0 으로 나온 덕에 결론이 더 또렷해졌지만, 그 카운터를 그대로 두면 다음에 진짜 빈
항목이 생겼을 때 못 잡는다」** 이 한 문장이다.

답이 맞게 나오면 거기서 멈추는 것이 보통이다. **맞은 답과 맞은 셈법을 갈라 본 것**이
두 번째 버그를 잡았다. 그리고 헛값을 찍은 옛 백그라운드 작업을 「직접 프로세스를 확인해서
살아 있는 것을 보고 버렸다」고 적은 것도 같은 성격이다 — 안 맞는 값이 나왔을 때 그것부터
의심한 것.

3시간 값도 좋다. 500개에서 **90분 넘게 546MB 에서 한 자리도 안 움직였다**는 것은
「안 샌다」를 이제 자신 있게 말할 수 있게 한다.
