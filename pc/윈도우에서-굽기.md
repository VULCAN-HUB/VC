# 윈도우에서 VC 굽기

맥에서 만든 소스를 윈도우 PC 로 옮겨 **거기서** `VC.exe` 를 굽는다.
`.exe` 는 크로스컴파일이 안 된다 — 윈도우 것은 윈도우에서만 나온다.

## 0. 꾸러미 받기

`VC-소스-윈도우용.zip` (4MB 남짓) 하나면 된다. 안에 `pc\` 가 통째로 들어 있다.
**모델·venv·dist 는 안 들어 있다** — 기계마다 다르고 무겁다.

받는 길(아무거나):

- **테일드롭**: 맥에서
  `tailscale file cp ~/projects/_빌드파일/VC-소스-윈도우용.zip <윈도우이름>:`
  윈도우에서 `tailscale file get .`
- USB · 공유 폴더 · 메일 첨부 — 4MB 라 무엇이든 된다

## 1. 풀기

작업하던 자리에 푼다(전에 쓰던 `pc\` 가 있으면 **그 위에 덮어쓴다** — 새 파일이
몇 개 늘었다: `mesh.py` · `vcmcp.py` 등).

```
D:\프로젝트\VC\pc\     ← 여기에 풀었다고 치자
```

## 2. 파이썬 채비 (처음 한 번만)

전에 굽던 PC 면 이미 되어 있다. 새로 하는 거면:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install pyinstaller PyQt5 onnxruntime tokenizers llama-cpp-python `
            faster-whisper sounddevice segno piper-tts
```

★ 맥용 목록(`requirements-mac.txt`)은 **그대로 쓰면 안 된다** — Metal 판이 섞여 있다.

## 3. 굽기

```powershell
.\build.ps1
```

**스스로 자체점검(56개)을 먼저 돌리고**, 통과해야 굽는다. 안 통과하면 안 구워진다 —
「윈도우에서만 나는 탈」이 설치본에 실리지 않게 하려는 것이다.

결과: `D:\프로젝트\_빌드파일\` (바꾸려면 `.\build.ps1 -OutDir 어디`)

## 4. 모델 넣기

굽는 데는 필요 없고 **돌리는 데** 필요하다. 맥 쪽 `models\` 에 있는 것과 같은 것을
윈도우 모델 자리에 둔다:

- `qwen3-8b.gguf` (대화)
- `e5-base\` (뜻 검색)
- `piper\` (말하기)

자리를 모르겠으면 VC 를 한 번 켜 보면 **어디에 넣으라고 말해 준다.**

## 5. 창고 자리 (여러 기계로 이어서 일할 때)

창고를 NAS·공유 폴더에 두고 맥·윈도우가 **같은 창고**를 본다.
기계마다 쪽지 한 장:

- 윈도우: `VC.exe` 옆에 `기록자리.txt`, 안에 그 기계에서 보이는 경로 (`Z:\VC`)
- 맥: `~/Library/Application Support/VC/기록자리.txt`, 안에 `/Volumes/NAS/VC`

★ 색인 db 는 **기계마다 따로** 만들어진다 — 네트워크 위에서 SQLite 를 쓰지 않는다.

## 6. 기기끼리 신호 (선택)

저장·지움을 누르면 붙어 있는 다른 기기가 바로 안다. 훑기를 기다릴 필요가 없다.

1. 테일스케일을 양쪽 다 켠다
2. 설정 → **기기끼리 신호** → 「새 열쇠 만들기」
3. 나온 값을 **모든 기계에 똑같이** 넣는다 (영문·숫자만)

주소는 안 적는다 — 테일스케일로 서로 찾는다.

## 걸릴 만한 자리

| 증상 | 까닭 |
|---|---|
| 켤 때 방화벽이 묻는다 | 서버가 8765 를 연다. **허용**해야 폰·딴 PC 가 붙는다 |
| `claude` 를 못 찾는다 | `npm i -g @anthropic-ai/claude-code` 뒤 새 터미널에서 |
| 자체점검이 멈춘다 | 통과 못 한 것이 있다. 그 줄을 그대로 들고 오면 된다 |
| 창고가 비어 보인다 | `기록자리.txt` 가 가리키는 자리를 확인 — 못 쓰는 자리면 기본 자리로 켜진다 |
