# 0. 네가 낸 판단 몫을 **그대로** 넣었다

네가 적어 준 것:

```
--doctor 에는 벡터 개수와 함께 같은 검색 서비스가 실제로 읽는 Notes 인스턴스로
semantic() 왕복을 한 번 시키는 값이 알맞다.
검사 글 한 장을 골라 그 글의 본문 일부를 질의로 쓰되 낱말 검색은 끄고 뜻 검색만
실행해야 한다. 혼합 검색이면 임베더가 빠져도 낱말 일치가 결함을 가릴 수 있다.
성공 줄은 ✔, 결과가 없거나 다른 글이면 ✘, 항목 0개나 모델 없음이면 못 잼으로 갈라야 한다.
```

**넷 다 그대로 했다.** 「낱말 일치가 결함을 가린다」는 지적이 핵심이었다 — 그래서
`search()` 를 안 쓰고 `semantic()` 을 곧장 부른다. 그리고 네 마지막 말
「이 검사는 뜻 품질을 보증하지 않는다」도 코드 주석에 그대로 적어 뒀다.

[잰 것, 만든 PC] 글 2장짜리 창고에서:
```
뜻 왕복 = ✔ 「김치찌개 끓이기」 로 물어 1등 「김치찌개 끓이기」 · 가까움 0.908
벡터 없는 창고에서는 = 못 잼 — 벡터가 있는 글이 없다
```

## 두 번째 것 — 네가 「못 쟀다」고 적은 그것

```
너: --no-ui 의 stdout/stderr 를 파일로 받았지만 [뜻 벡터] 줄은 남지 않았다
```

**네 방법이 틀린 게 아니라 그 줄이 갈 데가 없었다.** 구운 판은 `--noconsole` 로
굽기 때문에 `sys.stdout` 이 아예 `None` 이고, `print` 는 조용히 사라진다.
**창 없는 판에 콘솔 알림을 넣은 것 자체가 틀렸다.** 이제 `vc-기록.log` 에도 적는다.

# 3. 판단 몫 (하나만)

**「뜻 왕복」이 ✘ 를 낼 진짜 자리를 어떻게 만들어 볼까.**
지금 이 검사는 만든 쪽에서 ✔ 와 「못 잼」만 봤다 — **✘ 가 나오는 것을 아직 아무도 못 봤다.**
검사가 진짜로 무는지는 ✘ 를 한 번 봐야 안다(이 프로젝트 규칙이다: 되돌리면 터져야 한다).
네가 손댈 수 있는 범위에서 ✘ 를 만들 길이 있을까 — 예를 들어 모델 폴더 이름을 잠깐 바꾸거나,
벡터 표만 비우거나. **위험하면 하지 말고 「이렇게 하면 될 것 같다」만 적어도 된다.**
