# 물음 1 답 — **네 자료는 멀쩡하다. 같은 글이 기계마다 다르게 판정된다**

자료 올려 준 것 잘 받았다. **내 자리에서 똑같이 돌렸다.** 새 판은 없다(v0.1.84 그대로).

---

# 1. 잰 것 — 같은 자료 · 같은 모델 · 같은 판

```
네 자리에서 남은 것 (3개)
  검색 색인 설계 결정 · 입력과 경계 조건 · 저장과 중복 방지

내 자리에서 남은 것 (4개)
  검색 색인 설계 결정 · 저장과 중복 방지 · 검색과 필요한 부분 읽기 · **로컬 문서 백업 절차**
```

★ **네가 「기대와 다르다」고 한 백업 절차 글은 내 자리에서 남았다.**
갈래도 「일」로 제대로 붙었다. **글 탓이 아니다.**

## 내 자리에서 두 번 돌리면 값이 같다

```
1번째: 결정 · 검색과 읽기 · 백업 절차 · 저장과 중복      4/8
2번째: 똑같다                                        4/8
```

→ **한 기계 안에서는 되풀이된다. 기계가 바뀌면 갈린다.**
같은 모델 파일(해시 일치)에 같은 판인데도 그렇다. 도는 자리(CPU 갈래·실 개수·llama.cpp
셈 차이)가 다르면 **같은 물음에 다른 답**이 나온다.

# 2. 그래서 무엇이 참인가

```
✔ 네 판정 기대는 옳다 — 백업 절차 설명은 남아야 하는 글이다
✔ 네 자료도 옳다 — 다시 만들 것 없다
✘ 「문지기 판정」은 기계 사이에서 견줄 수 있는 잣대가 아니다
```

★ **이건 잣대 쪽 이야기다.** 앞으로 문지기 결과는 이렇게 다룬다:

```
견줄 수 있는 것    한 기계에서 두 번 돌린 값 (되풀이되나)
                남는 쪽/버리는 쪽의 **비율**과 **방향** (잡담·로그가 버려지나)
견줄 수 없는 것    네 자리와 내 자리의 「어느 글이 남았나」 목록
```

□ 네 자리에서도 **같은 폴더를 두 번** 돌려 봐 줘 (`--흡수` 만, 세어만).
  같은 값이면 「기계 사이 차이」로 닫히고, 다르면 **그건 딴 결함**이다.

# 3. 안 고치는 까닭 — 넓게 구하면 더 나빠진다

「버린다고 해도 설명글이면 구한다」로 넓힐 수는 있다. 안 한다:

```
[예전에 잰 것] 「규칙」이라는 낱말이 어디든 있으면 구하기
              → 막은 것의 21~33%가 되살아났고, 되살아난 것이 규칙도 아니었다
[지금 규칙]   줄 앞에 「규칙:」「결정:」 딱지가 있을 때만 구한다
              → 1260 조각에서 49개(3.9%)만 걸리고 헛구제가 없다
```

넓히면 **문지기를 켠 뜻이 사라진다**(과정 소음이 그대로 항목이 된다).
**작은 모델의 판정이 기계마다 갈린다는 사실 자체**를 오너에게 올렸다 — 이건
잣대를 조정할 일이 아니라 **어떤 모델을 쓸지의 문제**다.

# 4. 이어서 재 줄 것

```
□ 같은 폴더 두 번 흡수 (2번 물음) — 네 자리에서 되풀이되나
□ 지시서 05 의 「다·라·마」 — 장문 부분 읽기 · 엔진 줄 · 안 바뀔 것
□ 윈도 보안 창이 아직 앞에 있으면 --no-server 로 창 쪽만 재라 (갈라서 적어라)
```

★ 네가 「소규모 자체자료라 일반 성능으로 확대해석하지 않는다」고 미리 못 박아 둔 덕에
이 값을 그대로 쓸 수 있었다. 확대해서 적었으면 **틀린 결론(문지기가 설명글을 버린다)**이
기록으로 남았을 것이다.
