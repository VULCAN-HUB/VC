# VC v0.1.81 — **꺼내기를 두 단으로 갈랐다.** AI가 읽는 값이 98% 줄었다

오너 지시로 들어간 것이다. 창은 안 바뀐다 — **바뀐 것은 서버가 주는 값의 모양**이다.

---

# 1. 무엇이 문제였나

`/eb/v1/memory/search` 는 걸린 여덟 장의 **몸을 통째로** 줬다.

```
[잰 것] 개발 창고 100장 · 물음 다섯 개
        예전 747,823자 (≈ 299,000토큰)   →   1단 16,022자 (≈ 6,400토큰)
        줄어든 몫 97.9%   물음 하나는 223,753자 → 1,927자 (116배)
```

기록 한 장이 평균 5,814자 · 최대 184,467자다. **여덟 장이면 46,000자가 나가는데
실제로 읽는 것은 몇 줄이다.** 글이 큰 게 문제가 아니라 **꺼내는 단위가 통짜**인 게 문제였다.

# 2. 어떻게 바꿨나 — 두 단

```
1단  GET /eb/v1/memory/search?q=...
     title · summary(한 줄) · headings(소제목 이름들) · chars(글자 수) · links
     ★ body 를 안 준다

2단  GET /eb/v1/memory/note?title=...&heading=...
     그 소제목 아래 한 토막만 준다. heading 없이 부르면 글 한 편을 그대로 준다
```

- `summary` 는 앞머리에 `요약:` 이 있으면 그것, 없으면 몸의 첫 문장(120자)이다.
- **없는 소제목을 부르면 글 통째를 안 준다.** 404 로 「없다」고 하고 **있는 소제목을 보여 준다** —
  아끼려던 것이 그대로 나가면 안 하느니만 못하다.
- **붙여 쓰던 쪽은 안 깨진다** — `?full=1` 을 붙이면 예전처럼 `body` 가 온다.

사람 쪽은 안 바뀐다. 다만 **소제목을 잘 달면 그게 곧 AI 의 꺼내기 단위**가 된다.

# 3. 재 줄 것

## 가. 받자마자
```
sha256 · 제품 버전 0.1.81.0 · 창 제목 「VC」 · 메모리 · 죽음기록
```

## 나. ★ 두 단 꺼내기 — 이번 판 본론

서버가 떠 있어야 한다(그냥 켜면 뜬다). 토큰은 `--doctor` 의 페어링 토큰이다.
※ **토큰은 보고서에 적지 마라.** 값이 아니라 「됐다/안 됐다」만 적으면 된다.

```
1단   GET http://127.0.0.1:8765/eb/v1/memory/search?q=<찾을말>
      Authorization: Bearer <토큰>
□ 결과에 body 가 **없나**            ← 있으면 이번 판이 안 먹은 것이다
□ summary · headings · chars 가 있나
□ 통째로 몇 자인가 (예전과 견줄 수 있게 자릿수만 적어 줘)

2단   GET .../eb/v1/memory/note?title=<제목>&heading=<소제목>
□ **그 토막만** 오나 (다른 칸 내용이 안 섞이나)
□ 없는 소제목을 주면 404 + headings 목록이 오나  ← 글 통째가 오면 잘못이다
□ heading 없이 부르면 글 한 편이 오나

되돌아가는 길
□ ...?full=1&q=... 이면 예전처럼 body 가 오나
```

★ **네 큰 기록(740장)에서 1단이 몇 자인지**가 제일 값진 값이다. 내 쪽은 100장짜리다.

## 다. 이건 안 바뀌어야 한다
```

빈 글 뭉치 3 · 치울 것 20 · TC-09 · TC-11
찾기점수 ① 11 · ③ 15 · 적합률 8/740 · 항목 740 · 그물 163쌍 · --doctor 듣는 자리
```
★ **창 검색은 서버를 안 거친다**(같은 파일을 본다). 창에서 찾기가 그대로여야 맞다.
