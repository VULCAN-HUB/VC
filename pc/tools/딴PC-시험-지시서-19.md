# VC v0.1.56 — 메모리가 이제 창을 잰다

**네가 25-1 에서 찾은 것이 맞았다.** `--report` 가 창이 아니라 자기 프로세스를
쟀다. 그래서 41MB · 켠 지 0분 0초 가 45초 뒤에도 그대로였고 「다시 봐라」가
영영 안 사라졌다. 네 진단 그대로다 — 재는 대상이 틀렸다.

## 고친 길 — 네가 짚은 그대로

자전(`vc-자전.json`)과 같다. **창이 4초마다 제 메모리를 `vc-메모리.json` 에 적고,
`--report` 는 그 파일을 읽는다.** 잰 때(벽시계)를 같이 적어서, 창이 자거나 꺼져
파일이 안 갱신되면 이렇게 말한다:

```
494MB (최고 511MB · 켠 지 3분 12초)                      ← 창이 살아 적고 있다
494MB (최고 511MB · 켠 지 5분 0초)  ← **61초째 안 갱신 — 창이 자거나 꺼졌다. 이건 그때 값**
창이 아직 안 적었다 (창이 떠 있어야 잰다)                 ← 창이 한 번도 안 떴다
```

끝에서 끝까지 실증했다 — 창을 띄우고, 딴 프로세스로 같은 파일을 읽으니
**둘이 같은 값**이 나왔다(창 90MB = 딴 프로세스 90MB). 고침 전이면 딴 프로세스는
제 41MB 를 봤을 것이다.

## 재 줄 것

**뜬 직후와 30초 뒤, 두 번 뽑아라.**

```
뜬 직후:  ____MB · 켠 지 ____   「다시 봐라」 붙었나?
30초 뒤:  ____MB · 켠 지 ____   「다시 봐라」 사라졌나?  ← 이번엔 사라져야 한다
```

★ 이번엔 **켠 지가 자라야 한다.** 지난 판은 늘 0분 0초였다. 자라면 고쳐진 것이다.

한 가지 더 — 창을 **끄고** `--report` 를 뽑아 봐라. 「안 갱신 — 창이 자거나
꺼졌다」가 붙는지. 붙으면 낡은 값을 낡았다고 말하는 것이다.
