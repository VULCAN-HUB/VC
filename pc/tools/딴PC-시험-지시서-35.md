# 2. v0.1.75 에 든 것 — `--판올리기` (네가 못 받은 판)

다시 붓기는 **색인을 새로 만드는 수단이지 노트를 고치는 수단이 아니다**(사람 손질을
지운다). 그래서 노트를 고쳐야 하면 이 길로 온다.

```
0판 → 1판 :  스키마 칸 박기 · 앞머리 두 겹 올리기 · 제목의 `--` 빼기(이름 바꾸기)
[잰 것]      붓기 전 사본 3142장(전부 0판) → 3107장 고치고 이름 35개 → 옛 판 0장
             다시 돌리면 0장 (멱등)
```

**만들다 진짜 버그 둘을 잡았다:**

1. **이름을 바꾸면 출처·지은이가 통째로 사라졌다.** `rename` 이 `extra` 를 버렸다.
   출처는 **원본 사실이라 되살릴 수 없다.** 게다가 그 탓에 흡수분 35개가
   「사람이 만든 글」로 보여 막이가 막아섰다 — **안전장치가 제 잘못된 자료에 걸렸다.**
2. **이름 바꾸기가 실패하면 그 항목이 두 고리 사이로 빠졌다**(3142장 중 1장).
   순서를 뒤집어 이름부터 바꾸고 남은 것을 모두 줍게 했다.

※ 내 재는 법도 틀렸다 — 「앞머리 두 겹 122장」은 **본문의 가로줄**을 오해한 것이고
  **진짜 두 겹은 0장**이었다.

# 3. v0.1.76 에 든 것 — 네가 잡은 짝짓기 바닥값

> **13071자가 같은 것과 두 글자가 같은 것을 한 잣대로 다루면 안 된다.**

네 말이 맞다. 본문만 보고 짝을 지어 **두 글자짜리 셋**이 한 뭉치가 됐고, 제목이 서로
다른 딴 글이 「치울 것」에 들어갔다(`활동두번째`·`줄이 겹친다`·`띄우기시험`).

**흡수의 「너무 짧다」와 같은 바닥값(40자)을 쓴다.** 그 밑은 짝을 안 짓는다.

```
[잰 것] 두 글자 본문 셋 + 긴 사본 한 쌍
        → 뭉치 1개 · 치울 것 1장   (짧은 셋은 안 묶인다)
        미리보기에 「본문 40자 미만은 짝을 안 짓는다」가 찍힌다
```

## 네 물음 2 — 표에 칸을 더한다

```
새 흡수 (지은이 있음)         → 기계
옛 흡수 (출처만 있음)         → 기계
사람이 만든 글 (출처 없음)     → 사람
사람이 고친 흡수분            → 사람
**앞머리가 아예 없는 글**      → **사람**   ← 네 552장이 여기다
```

★ **네 판정이 옳다.** 앞머리가 없는 글은 사람이 손으로 만든 글과 **구별할 수가 없다.
안 치우는 쪽이 옳다.** 그리고 **552 는 새 규칙대로 바르게 센 값**이고, 틀린 것은
「552 가 옛 흡수분일 것」이라던 **내 짐작** 쪽이었다.

# 4. 재 줄 것

## 가. 받자마자
```
sha256 · 제품 버전 0.1.76.0 · 창 제목 「VC」 · 메모리 · 죽음기록
```

## 나. ★ 짝짓기 바닥값 — 이번 판 본론
```
VC.exe --사본치우기        ← 세어만 본다
□ 「본문 40자 미만은 짝을 안 짓는다」가 미리보기에 찍히나
□ 뭉치·치울 것이 **22장에서 줄었나**  ← 두 글자짜리가 빠져야 한다
□ 「활동두번째」·「줄이 겹친다」·「띄우기시험」이 **치울 것에서 사라졌나**
□ 긴 사본(8월 회의록 · 아주 긴 메모 · 열 줄 메모)은 **그대로 남아 있나**
```

## 다. `--판올리기` — 네가 처음 보는 것
```
VC.exe --판올리기          ← 세어만 본다. 아무것도 안 고친다
□ 「올릴 것」 몇 장 · 셋(스키마·앞머리·제목)이 각각 몇인가
□ 「이름이 바뀔 것」 미리보기가 그럴듯한가 (`--` 만 빠지고 뜻은 남나)
```
★ **여기서 멈춰라. 올리면 「옛 판이 섞인 시험대」가 사라진다.**
올릴지 말지는 오너가 정한다 — 네 자리는 이 기능의 **유일한 시험대**다.

## 라. 이건 안 바뀌어야 한다
```
찾기점수 ① 1등 11 · ③ 1등 15 · 머리글 찍기
판 적합률 8/740 · 항목 740 · 연결 10 · 옛 판 732 · 그물 163쌍
목차(922 접힘 · 1500 위 줄) · [[링크]] 눌러 가기 · 앞머리 한 겹
```

# 5. 명령에 곁딸린 것 (다 적는다)

```
--사본치우기 [--쓴다] [--손댄것도쓴다]
--판올리기   [--쓴다] [--손댄것도쓴다]
    (없이)         세어만 본다 — **막이는 쓰기 앞에만 선다. 세는 건 늘 된다**
    --쓴다          고친다/치운다 (지난 판을 `.이력/` 에 남긴다)
    --손댄것도쓴다    사람 손댄 기록이 있어도 한다

--찾기점수 [물음파일] [--빼고 <출처조각>] [--제목벡터빼고]
    물음 한 줄 꼴 : 물음 | 정답   또는   물음 | 정답1; 정답2
--흡수 <폴더> [--쓴다] [--그래도쓴다]
--doctor · --report · --색인다시 · --이음선 · --도움말 · --check
```

# 6. 네가 세운 규칙들 — 내 쪽에도 다 옮겼다

```
값이 똑같으면 「달라진 게 없다」가 아니라 「안 먹은 것 아닌가」를 먼저 묻는다
스위치를 걸었으면 머리글에 그 몫이 찍혔는지 먼저 본다
고침이 무엇을 **안** 바꾸는지도 잣대에 넣는다
앞뒤가 다르면 **어느 쪽이 틀린지**부터 묻는다 (회귀와 반대 방향이다)
확정 못 하는 것은 지우지 말고 [짐작이다]로 남긴다
모르는 것은 모른다고 적는다 — 그게 가장 빨리 닫히는 길이다
둘만 놓고 견준 결과는 다 놓고 견준 결과와 다르다
탓을 하나로 묶기 전에, 그 탓을 빼고 다시 재는 길이 있는지 본다
눈으로 못 세겠으면 세어 주는 것을 찾는다 · 명령을 찾았으면 곁딸린 것도 본다
「새것이 왔나」는 셈이 아니라 이름으로 본다
누르기 전에 커서 모양부터 값으로 묻는다
```

내 쪽에서 보탠 것:
```
「들어 있나」로 소스를 보면 검사가 제 꼬리를 문다 — 세어서 본다
새로 만드는 길과 올려 쓰는 길은 다른 길이다
막이는 쓰는 것을 막아야지 보는 것을 막으면 안 된다
작은 자리에서 본 것은 「그럴듯하다」까지만 적는다
```
