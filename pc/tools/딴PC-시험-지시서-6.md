# VC v0.1.6 재시험 — 지시서 6

6차 보고서의 **회차별 표**가 원인을 그대로 짚어 줬다.

```
1회차  정상
2회차  헛뜸
3회차  헛뜸
```

**BOM 이 아니었다.** BOM 가설로는 1회차만 정상인 것을 설명 못 한다.

진짜 원인: 저장한 뒤에 **「연 순간의 글」을 안 고쳤다.** 그래서 두 번째 저장 때
디스크에 있는 글(= 내가 방금 쓴 것)이 「연 순간의 글」(맨 처음 것)과도
「새로 친 글」과도 달라서, **자기가 쓴 것을 남이 쓴 것으로 봤다.**
한 줄 고쳤다. BOM 은 v0.1.5 에서 이미 제대로 읽히고 있었다.

> 저장할 때 BOM 을 떼는 것은 사실이다(그쪽 관측이 맞다). 다만 그게 이 증상의
> 원인은 아니었다. 파일은 앞으로도 BOM 없는 UTF-8 로 쓴다 — 한 가지로 맞추는 게
> 옵시디언·git 과 섞어 쓸 때 낫다.

## v0.1.6 에서 바뀐 것

| # | 무엇 |

| 1 | **헛뜨던 「밖에서도 고쳤길래」 안내** — 저장 뒤 기준을 갱신한다 |
| 2 | **모르는 종류를 안 지운다** — 없는 값이면 맨 앞으로 떨어지고 다음 저장에 그게 파일에 쓰여 남의 값이 사라졌다 |

### 곁가지 하나 — 내 지시서가 틀렸다

`kind: "skill"` → 콤보 「모듈」 은 **원래 그렇게 정한 것**이다. 지시서 5 가
「선로」를 기대한다고 쓴 게 오기다. (콤보는 에이전트/모듈/**선호**/장소/물건/메모.
「선로」가 아니라 「선호」다.)

`kind: "장소"` → 「에이전트」로 떨어지던 것은 진짜 문제였고 고쳤다. 우리가 아는 키는
`agent · skill · preference · place · thing · note` 여섯뿐이라, 한글 값 「장소」는
모르는 값이다. 이제 그런 값도 그대로 보이고 그대로 저장된다.

## 1) ★★ 헛뜨던 안내 — 6차와 **똑같은 절차**로

6차에서 3번 중 2번 떴다. 이번엔 **다섯 번** 돌려 달라.

1. 씨앗 하나 깔고(BOM 붙여도 되고 안 붙여도 된다) VC 켜기
2. 그 항목 열어 「고치기」
3. 본문 한 줄 고치고 「읽기」 — **다섯 번 반복**
4. **밖에서는 아무것도 안 건드린다**

| 회차 | 아래 띠 문구를 그대로 적어 달라 |
|---|---|
| 1 | |
| 2 | |
| 3 | |
| 4 | |
| 5 | |

**「밖에서도 고쳤길래」가 한 번이라도 뜨면 실패다.**

### 1-1) 진짜 외부 변경일 때는 여전히 떠야 한다

고친 게 과하면 **진짜 외부 변경까지 놓친다.** 그것도 같이 본다.

1. 항목을 「고치기」로 열고 본문에 `내가친글` 치기
2. **저장하지 말고**, 밖에서 그 파일에 한 줄 덧붙이기

```powershell
Add-Content (Get-ChildItem $N -Recurse -Filter "허리 통증.md").FullName "`n진짜밖에서" -Encoding UTF8
```

3. 5초쯤 기다렸다가 「읽기」로 저장

| 확인 | 통과 기준 |
|---|---|
| 안내 | 「밖에서도 고쳤길래 … 「지난 판」에 남겼어」가 **떠야 한다** |
| 현재 파일 | `내가친글` 이 있다 |
| `.이력` | 어딘가에 `진짜밖에서` 가 있다 |

**1번은 안 뜨고 1-1 은 떠야 통과다.** 둘 중 하나만 맞으면 실패로 적어 달라.

## 2) 모르는 종류를 안 지우나

```powershell
$body = @"
---
kind: "장소"
---

여긴 어디.
"@
Set-Content (Join-Path $N "남의종류.md") $body -Encoding UTF8
```

VC 켜고:

| 확인 | 통과 기준 |
|---|---|
| 콤보 표시 | **「장소」** 그대로 (6차엔 「에이전트」로 떨어졌다) |
| 고치기 → 본문 한 줄 고치고 저장 → 파일 | `kind: "장소"` 가 **그대로** 있다 |
| 다른 항목으로 옮긴 뒤 콤보 | 목록이 **여섯 개**로 돌아온다 (에이전트/모듈/선호/장소/물건/메모) |

세 번째가 중요하다 — 자리를 안 치우면 항목을 옮길 때마다 목록이 길어진다.

또 하나: `kind: "skill"` 이 「모듈」로 뜨는 것은 **정상**이다. 그건 통과로 적어 달라.

## 안 고친 것 · 알고 있는 것

- **별칭 색인이 즉시 안 갱신되던 것** (6차 1번 ※) — 두 파일이 **같은 별칭**을 가졌다가
  한쪽을 바꾼 상황이었다. 별칭은 저장소에서 하나뿐이라, 임자가 사라지면 나머지 파일이
  다시 읽힐 때까지 빈자리가 된다. 드문 자리라 지금은 안 고친다. **알고 남긴다.**
- **카드 위 줄 정렬** — 오너 판단 대기. 제목을 윗줄로 올리면 이름 고치는 자리가
  좁아져서 그 결정이 먼저다.

시험 도구 쪽 기록(PostMessage 로 창에만 넣기, 한/영 때만 물리 키, 창 개수 세기 판정)
잘 봤다. 5차에 도구가 스스로 멈춘 것까지 적어 준 덕에 다음 판정 방법을 믿을 수 있다.
