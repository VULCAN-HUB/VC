# VC v0.1.5 재시험 — 지시서 5

5차 보고서로 **Esc 가 네 번 만에 끝났다.** 그리고 두 관측이 각각 버그 하나씩을 잡았다.

- **「팝업 창 클래스가 `Qt5152QWindowPopupDropShadowSaveBits` — 별개 최상위 창이다」**
  → 추정이 맞았다. 주 창에 건 스타일시트는 그 목록에 안 내려간다. 목록에 **직접** 입혔다.
- **「BOM 붙은 UTF-8 이라 정규화를 외부 변경으로 본 게 아닌가」**
  → 맞았다. **그리고 생각보다 컸다.**

## BOM 이 왜 큰 문제였나

`utf-8` 로 읽으면 BOM 이 **글자로 남는다.** 그러면 파일 첫 줄이 `---` 가 아니라
`(BOM)---` 이 되어 **프론트매터가 통째로 안 읽힌다** — 별칭·태그·종류가 사라진다.

윈도우 메모장과 PowerShell 5.1 `Set-Content -Encoding UTF8` 이 BOM 을 붙인다.
**즉 사람이 메모장으로 만든 글은 프론트매터가 전부 무시되고 있었다.**
「밖에서도 고쳤길래」가 헛뜬 것은 그 증상의 겉면이었다.

`utf-8-sig` 로 읽는다.

## 1) ★★ BOM — 이번의 핵심

**BOM 붙은 것과 안 붙은 것을 나란히 깔아 대조한다.** 3차에 그쪽이 제안한 그 방법이다.

```powershell
New-Item -ItemType Directory -Force $N | Out-Null

$front = @"
---
kind: "skill"
aliases: 딴이름
---

본문이다. #봄태그 [[이을 것]]
"@

# BOM 붙음 (PowerShell 5.1 의 UTF8 은 BOM 을 붙인다)
Set-Content (Join-Path $N "BOM있음.md") $front -Encoding UTF8

# BOM 없음 (대조군)
[IO.File]::WriteAllText((Join-Path $N "BOM없음.md"), $front,
                        (New-Object Text.UTF8Encoding $false))

# 실제로 BOM 이 붙었는지 눈으로 확인
foreach ($f in "BOM있음.md","BOM없음.md") {
  $b = [IO.File]::ReadAllBytes((Join-Path $N $f))[0..2]
  "$f  앞 3바이트: $($b -join ',')   (BOM 이면 239,187,191)"
}
```

VC 를 켜고(그 창에서) 확인:

| 확인 | 통과 기준 |
|---|---|
| **종류** | 두 항목 다 카드 위 콤보가 **「선로」(skill)** 여야 한다. 「메모」면 실패 |
| **별칭** | 다른 항목 본문에 `[[딴이름]]` 을 넣으면 **BOM있음** 으로 이어져야 한다 |
| **태그** | 아래 줄에 `#봄태그` 가 떠야 한다 |
| **본문 첫 글자** | 본문 맨 앞에 이상한 문자가 안 보여야 한다 |

**BOM있음 과 BOM없음 이 똑같이 동작하면 통과.** 다르면 그 차이를 적어 달라.

### 1-1) 헛뜨던 안내가 사라졌나

BOM 붙은 항목을 열어 「고치기」 → 본문 한 줄 고치고 「읽기」.

**밖에서 아무것도 안 건드렸는데 「밖에서도 고쳤길래…」 안내가 뜨면 실패다.**
5차에 이게 헛떴다. 두세 번 반복해서 봐 달라.

## 2) ★ `[[` 목록 옷 (두 판 연속 미통과)

「고치기」에서 `[[` 를 쳐서 목록을 띄우고 **눈으로** 본다.

| 확인 | 통과 기준 |
|---|---|
| 배경 | **어둡다** (흰 바탕이면 실패) |
| 글씨 | 밝은 색 |
| 고른 줄 | **주황 계열** (파란 막대면 실패) |
| 테두리 | 주황 얇은 선 |
| 스크롤 막대 | 가늘고 어둡다 (시스템 회색이면 적어 달라) |

바로 옆 콤보(메모 / 지난 판 / 목차) 펼침 목록과 **나란히 놓고 견줘** 달라 —
그쪽이 5차에 「대비가 더 도드라진다」고 한 그 비교다. 이제 같아 보여야 한다.

화면 캡처가 막히면, 그쪽이 쓰던 창 개수 세기로는 색을 못 본다.
그때는 **「못 봤다」** 로 적어 달라. 추측으로 채우지 말고.

## 3) `--예외시험` — 로그 폭증 방어 (5차에 못 잰 것)

일부러 예외를 500번 내는 스위치를 넣었다.

```powershell
.\VC.exe --예외시험
```

콘솔에 안 찍히면(창 프로그램이라) 파일을 봐라:

```powershell
Get-Content "$env:VC_DATA\vc-예외시험.txt" -Encoding UTF8
Get-Content "$env:VC_DATA\vc-죽음.log" -Encoding UTF8 -Tail 20
```

| 확인 | 통과 기준 |
|---|---|
| 죽음 기록이 늘어난 양 | **1KB 안쪽**. 막지 않았다면 수십 KB 가 된다 |
| traceback 벌수 | **1벌**만 있어야 한다 |
| 횟수 표시 | 「같은 예외 2번째 / 10번째 / 100번째」 줄이 보여야 한다 |

만든 PC 에서는 **500번에 538바이트**였다. 그쪽 숫자를 적어 달라.

## 4) 되짚기

이번엔 고친 곳이 셋뿐이라 짧게만.

| 확인 | 기대 |
|---|---|
| `[[` 목록 Esc (영문 한 갈래면 충분) | 목록만 닫히고 카드는 남는다 |
| `이미지 다듬는 법` 검색 | 안 죽음. 1등 = 사진 보정 순서 |
| `Ctrl+N` → 제목 치고 → 본문 저장 | 파일에 본문이 있다 |
| 확인창 | 「지운다 / 그만둔다」, 파란 아이콘 없음 |
| 조각 창 · X 로 닫기 | 창 1개, 프로세스 소멸 + `끔 (0)` |
| 밖에서 고친 글 | 3초쯤에 화면에 온다 |

## 아직 안 고친 것 (알고 남김)

**카드 위 줄 정렬** (4·5차 8-3 라) — 가운데가 비고 제목이 아랫줄에 따로 있어
시선이 위→아래→위로 튄다는 지적. 제목을 윗줄로 올리면 **제목을 눌러 이름을
고치는 자리**가 바뀌는 것이라 오너 판단이 필요하다. 그 결정이 나면 손댄다.

지금까지 다섯 번 다 **본 대로만, 안 해 본 것은 「안 해 봄」, 추측은 추측으로** 적어 준
덕에 매번 원인을 짚었다. 특히 5차의 팝업 창 클래스와 BOM 두 줄은 각각 버그 하나씩을
곧바로 잡아 줬다. 그대로만 해 달라.
