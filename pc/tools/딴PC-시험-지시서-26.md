# VC v0.1.63 — 네가 「라」에서 찾은 셋, 다 고쳤다

지난 판까지 미뤄 뒀던 **옵시디언 대응 셋**을 고쳤다. 오너가 「설계·구조가 막히면
옵시디언 기능을 그대로 따르라」고 정해 둬서, 물어볼 것 없이 그 규칙대로 갔다 —
셋 다 옵시디언에서는 되는 것들이다.

## ★ ① `[[링크]]` 가 날것으로 보이던 것 — 셋 중 제일 컸다

재현하니 원인이 뚜렷했다:

```
[안 먹는 말투](note:안 먹는 말투)   ← 주소에 **빈칸**이 있어 Qt 가 링크로 안 만든다
```

**제목에 빈칸이 있는 것이 보통이라, 거의 모든 이음선이 날것이었다.**
링크 그물이 핵심인 물건에서 링크가 안 눌리고 있었다. 주소를 `<...>` 로 감싸 고쳤다.

```
[잰 것] 고치기 전: 앵커 0개 · 화면에 `[…](note:…)` 가 글자로 보임
        고친 뒤  : 앵커 생김 · 화면엔 「안 먹는 말투」만 · 누르면 그 항목으로 간다
```

## ② 목차가 안 보이던 것

카드가 **560px 보다 좁으면** 목차를 통째로 숨기는데, **「…」 에도 안 넣었다.**
네가 「메뉴에도 없다」고 한 것이 정확했다 — 갈 길이 사라진 것이다.

> **접는 것은 자리를 아끼려는 것이지 기능을 없애려는 것이 아니다.**

좁으면 「…」 안에 「목차 (N)」 으로 들어가고, 넓히면 다시 위 줄로 돌아온다.

## ③ 색상 코드가 태그색으로 칠해지던 것

네 말 그대로 **「뽑기와 색칠이 따로 논다」** 였다. 뽑는 쪽은 16진수를 거르는데
칠하는 쪽은 안 걸렀다. **또 같은 일이 두 군데** — 한 자리(`태그인가`)로 모았다.

```
배경은 #0E1116 이고 태그는 [#할일](<tag:할일>) 이다.    ← 색상 코드는 글자 그대로
```

# 재 줄 것

```
가. sha256 · 제품 버전 0.1.63.0 · 죽음기록 · 메모리

나. ★ ① [[링크]] — 이번 판 본론
    □ 읽기 모드에서 [[링크]] 가 **눌리는 모양**으로 보이나 (괄호·note: 안 보이나)
    □ 눌러서 그 항목으로 가나
    □ **빈칸 없는 제목**([[기록]] 같은 것)도 그대로 되나
    □ #태그 도 눌리나 · [[제목#소제목]] 도 되나
    □ 첨부(그림)가 그대로 보이나  ← 같은 자리를 건드렸다

다. ② 목차
    □ 카드를 좁혔을 때 「…」 에 「목차 (N)」 이 있나
    □ 거기서 소제목을 고르면 그 자리로 가나
    □ 넓히면 위 줄로 돌아오나 (그리고 「…」 에서는 사라지나 — 겹치면 안 된다)

라. ③ 색상 코드
    □ 본문의 #0E1116 이 이제 **안 칠해지나**
    □ 진짜 태그(#할일)는 그대로 칠해지고 눌리나
    □ 아래 태그 요약줄은 지난 판과 같나

마. 회귀 — 지금까지 통과한 것 전부
    "안 먹는 말투" 1등 · ④ 헛경고 안 뜸 · ⑥ 따옴표 좁힘 · 미리보기 `**` 없음
    따옴표 감싸기 네 자리 한 겹 · ⚠ 안 가려짐 · 말풍선 치워짐 · 앞머리 한 겹
```

## 이제 안 고친 것은 하나뿐이다

```
소급 — 옛 제목 `--` 15개 · 옛 프론트매터가 미리보기를 먹는 것   ← 오너 확인 대기
```

네가 「찾을 때마다 눈에 걸린다」고 적어 준 그것이다. 오너가 정하면 바로 한다.

## 이번에도 「같은 일이 두 군데」였다

③ 이 그랬다. 지난 판 따옴표 감싸기가 **넷**이었고, 이번 태그는 **둘**이었다.
둘 다 **한 자리로 모으고 나서야** 갈라져 있던 것이 보였다.
네가 말한 「몇 군데인가를 눈으로 세면 안 된다」가 계속 맞는다.
