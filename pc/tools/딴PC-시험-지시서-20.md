# VC v0.1.57 — 제목 고침 + 「사람이 실제로 쓸 때」를 본다

이번 판은 두 가지다. ①흡수 제목 버그(②) 고침, ②**이제부터 시험의 결이 바뀐다** —
버그 잡기에서 **「사람이 이걸 매일 쓰면 어디가 불편한가」**로.

## 왜 결이 바뀌나 — 오너가 큰 그림을 밝혔다

VC 는 네 기둥짜리 물건의 **1번**이다:

```
1. 영구 지식창고 (옵시디언 모델)      ← 지금 여기
2. 자가 진화·작업 실행 (헤르메스 모델)
3. 실시간 핸즈프리 (AR 글래스)
4. 원스톱 결과물 (젠스파크 모델)
최종: 모든 지식을 저장하고 스스로 진화하며 AR 로 일상을 보조하는 독립형 통합 AI
```

지금은 **1번(옵시디언 대체)** 을 다진다. 그러니 이번 시험의 잣대는 두 개다:
**㉠사람이 실제로 쓸 때 불편한가**, **㉡옵시디언 기능이 그대로 되는가.**

## 나. ② 제목 고침 — 이번 판 핵심 (흡수를 돌려야 보인다)

만든 쪽에서 오너 자료 3142장을 부어 재 보니 **제목이 다 갈라졌다**(전엔 log.md 한 표제
밑 72조각이 전부 「settings.json Stop 훅」이었다 → 이제 3142장 전부 다른 제목).

네 자리에서 **굵은 제목이 든 로그성 파일**로 `--흡수` 를 돌려 봐라(볼트 `log.md`
같은 것). 확인할 것:

```
--흡수 <로그성 폴더>            세어만 본다
제목에 -- 가 남았나?           (남으면 아직 안 고쳐진 자리 — 알려 줘)
같은 제목이 무더기로 있나?      (한 표제 밑 여러 조각이 다 같은 이름이면 못 고친 것)
로그 줄머리(「2026-08-09 | save |」)가 제목에 남았나?  (남으면 못 뗀 것)
```

잡음 폴더는 애초에 굵게 제목이 없어 안 갈린다(지난번 확인). **굵은 제목이 든 자료**로
재야 갈린다.

## 다. ㉠ 사람이 실제로 쓸 때 — 불편한 점·문제점 (이번 시험의 새 축)

**네가 오너라 치고 며칠 쓸 것처럼 굴어라.** 셈이 맞나가 아니라 **손에 거슬리나**를 본다.
아래를 실제로 해 보고, 걸리적거리는 것을 **하나도 빼지 말고** 적어라.

```
□ 글 하나 새로 쓰기(Ctrl+N) → 제목 치고 본문 쓰고 닫기 → 다시 열기.
   몇 번 눌러야 하나? 어디서 멈칫하나? 저장됐는지 불안한 순간이 있나?
□ 찾기: 생각나는 낱말로 검색 → 원하는 게 위에 오나? 몇 번째에 나오나?
   "분명 있는데 안 나온다" 가 있나?
□ 그래프: 열어서 이리저리 본다. 무엇이 보고 싶은데 안 보이나?
   점이 너무 많아 뭐가 뭔지 모르겠나? 선이 쓸모없어 보이나?
□ 오래된 것 찾기: 며칠 전/몇 주 전에 적었을 법한 것을 찾아본다. 손이 몇 번 가나?
□ 매일 쓴다면 제일 먼저 지겨워질 동작은? 제일 자주 할 동작이 제일 쉬운가?
```

★ **「이 정도면 되지」로 넘기지 마라.** 사람은 작은 거슬림 하나로 도구를 버린다.
  숫자로 못 재는 「답답함·불안·헷갈림」이 이번엔 정식 보고 대상이다.

## 라. ㉡ 옵시디언 기능이 그대로 되는가 — 하나씩 확인

VC 의 1번 목표는 **옵시디언 대체**다. 아래는 이미 만든 것들이다. **실제로 되는지**
하나씩 짚어라(된다/안 된다/이상하다 + 무엇이):

```
□ .md 파일로 저장되나 (옵시디언에서 그 폴더를 열면 그대로 보이나)
□ 프론트매터(type/date/status 등)가 저장 뒤에도 살아 있나 (지워지면 안 됨)
□ [[링크]] 로 노트끼리 이어지나 · [[ 치면 자동완성 뜨나
□ 할 일 [ ] / [x] 가 ☐/☑ 로 보이고 눌러서 켜고 끄나
□ 태그가 제대로 잡히나 (색상코드 #0E1116 같은 게 태그로 안 잡히나)
□ 목차(소제목 2개 이상)가 뜨나
□ 지난 판(이력) 이 남나 · 나란히 보기 · 뒤로/앞으로(Alt+←/→)
□ 오늘 일지·서식(Ctrl+D) 이 되나
□ 검색 문법: tag: path: kind: year: · "정확한 구절" · -빼기
□ 단축키 10개(Ctrl+O/F/E/N/S/D, Alt+←/→, Ctrl+\, Esc) 가 다 먹나
```

★ 옵시디언에서 되는데 VC 에서 안 되는 것을 찾으면 **그게 제일 값진 보고**다 —
  1번 목표가 「옵시디언 대체」라서다.

## 보고 형식 (지난번처럼)

- **안 잰 것을 「통과」로 적지 않는다.**
- 불편/문제는 **크기 순서 없이 다 적어라** — 걸러내는 건 이쪽에서 한다.
- 「이건 취향일까 버그일까」 싶은 것도 적어라(취향인 줄 알았던 게 버그였던 적이 있다).

## 안 건드린 것

- 그물의 ①(진짜 동일 사본)·③(맹탕 맞장구) 청소는 **오너가 미뤘다.** 그래서 그래프에
  아직 사본끼리 잇는 선이 남아 있다(near-중복 40%→29%로 줄었지만 0은 아니다).
  그물이 거슬리면 적되, 「사본 선이 남았다」는 이미 아는 것이다.
- 판 zip 은 지금 판 하나만 있으면 된다(옛것 지워도 됨).
